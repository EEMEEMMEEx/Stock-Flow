เปรียบเทียบผังกระบวนการทำงานระหว่างการนิยามสินค้า Master (`/items`) และการบันทึกรับของเข้าคลังจริง (`/stock-in`)

Items Master (Catalog) Stock In (Inventory Inbound)

1. Items Master Catalog Workflow (/items) — การนิยามสมุดทะเบียนวัสดุหลัก

กระบวนการสร้างและแก้ไขคุณลักษณะสินค้า (ชื่อ, SKU, หมวดหมู่, หน่วยนับ, รูปภาพ) โดยมีค่าสต็อกเริ่มต้นเป็น 0 เสมอ

1. หน้าที่หลัก (Primary Purpose) Master Data Catalog Definition
ทำหน้าที่เป็นสมุดทะเบียนกลางสำหรับนิยามและกำหนดคุณลักษณะของสินค้า/วัสดุอุปกรณ์ทุกชนิดในองค์กร 		Transactional Inventory Movement
ทำหน้าที่บันทึกธุรกรรมการรับวัสดุเข้าคลังจริงจาก Supplier เพื่อผูกเข้ากับโครงการและเพิ่มสต็อก
2. โครงสร้างข้อมูล (Data Attributes) • Name (ชื่อสินค้า)
• SKU (รหัสบาร์โค้ดสินค้า)
• Category ID (หมวดหมู่)
• Unit (หน่วยนับ: ชิ้น, ถุง, เส้น)
• Image DataURL (รูปภาพ) 		• Stock In Order ID (เลขที่บิลรับเข้า)
• Project ID (โครงการที่รับเข้า)
• Supplier (ผู้จัดจำหน่าย) & PO Number
• Item Quantity (จำนวนที่รับเข้า)
• Unit Price (ราคาต่อหน่วย)
3. ผลกระทบต่อสต็อก (Inventory Impact) ZERO STOCK IMPACT
การเพิ่มหรือแก้ไขสินค้าในหน้านี้ **ไม่เพิ่มและไม่ลดสต็อกสินค้า** สต็อกเริ่มต้นจะเป็น 0 เสมอจนกว่าจะมีบิลรับเข้า 		+ ACTUAL STOCK INCREASE
การบันทึกบิลรับเข้าจะทำการเพิ่มยอดสินค้าคงเหลือจริงในคลัง (`stock = stock + quantity`) สะท้อนใน `stock_balance`
4. รูปแบบอินเทอร์เฟซ (UI Interaction) Form Modal Input
ใช้งานผ่านฟอร์มป๊อปอัป (Create/Edit Dialog) เพื่อกรอกข้อมูลคุณลักษณะสินค้า และอัปโหลดภาพ Base64 		POS Terminal Cart Checkout
ใช้งานผ่านหน้าจอ POS Terminal เลือกสินค้าจาก Master ใส่ตะกร้า และเปิด Modal สรุปบิล Checkout
5. สิทธิ์การใช้งาน (RBAC Access) • Admin: เพิ่ม/แก้ไข/ลบ Master Data
• Staff: อ่านข้อมูลได้อย่างเดียว (Read-only) 		• Admin: บันทึกรับสินค้าเข้าคลัง
• Staff: ไม่มีสิทธิ์เข้าถึงเมนูนำเข้าสินค้า
6. ข้อผิดพลาดที่พบบ่อย (Anti-patterns) ❌ ห้ามกรอกจำนวนสต็อกในหน้า Items
ความเข้าใจผิดว่าเพิ่มสินค้าแล้วต้องมีสต็อกทันที (สต็อกจริงต้องเกิดจากการทำรายการรับเข้าที่หน้า /stock-in) 		❌ ห้ามแก้ไขชื่อสินค้าในหน้า Stock In
หน้า /stock-in ทำหน้าที่เลือกสินค้าที่มีอยู่แล้วในระบบ หากต้องการเปลี่ยนชื่อ/หน่วยนับ ต้องไปแก้ที่หน้า /items

Database Schema & Entity Relationship Architecture

เปรียบเทียบตารางฐานข้อมูลระดับ Master Data (`items`, `categories`) และระดับ Transaction (`stock_in_orders`, `stock_in_items`) พร้อม View คำนวณสต็อก

1. Master Data Tables (สมุดทะเบียนวัสดุหลัก) items & categories 
-- 1.1 Categories (หมวดหมู่)
CREATE TABLE public.categories (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL UNIQUE,
  description TEXT
);

-- 1.2 Items Master (รายการสินค้า)
CREATE TABLE public.items (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL,
  sku TEXT UNIQUE,
  category_id UUID REFERENCES public.categories(id),
  unit TEXT NOT NULL DEFAULT 'ชิ้น',
  image_url TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

ตาราง `items` เก็บเฉพาะคุณลักษณะของสินค้า ปราศจากคอลัมน์จำนวนสต็อกคงเหลือ

2. Transaction Ledger Tables (ธุรกรรมนำเข้าสต็อก) stock_in_orders & items 
-- 2.1 Stock In Orders (บิลรับเข้า)
CREATE TABLE public.stock_in_orders (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id UUID NOT NULL REFERENCES public.projects(id),
  supplier TEXT,
  po_number TEXT,
  received_date DATE DEFAULT CURRENT_DATE,
  created_by UUID REFERENCES public.profiles(id)
);

-- 2.2 Stock In Items (รายการในบิลรับเข้า)
CREATE TABLE public.stock_in_items (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  order_id UUID REFERENCES public.stock_in_orders(id),
  item_id UUID REFERENCES public.items(id),
  quantity INTEGER NOT NULL CHECK (quantity > 0),
  unit_price DECIMAL(12,2)
);

ตาราง `stock_in_items` ทำหน้าที่เก็บจำนวนที่นำเข้าจริง และเชื่อมโยงไปยัง `items.id`

3. Calculated Inventory View (การคำนวณยอดคงเหลือสุทธิ) stock_balance 
-- View คำนวณยอดคงเหลือสต็อกสุทธิ (Stock In Total - Withdrawal Approved Total)
CREATE OR REPLACE VIEW public.stock_balance AS
SELECT 
  i.id AS item_id,
  i.name,
  i.sku,
  COALESCE(in_sum.total_in, 0) - COALESCE(out_sum.total_out, 0) AS balance
FROM public.items i
LEFT JOIN (
  SELECT item_id, SUM(quantity) AS total_in
  FROM public.stock_in_items GROUP BY item_id
) in_sum ON in_sum.item_id = i.id
LEFT JOIN (
  SELECT wi.item_id, SUM(wi.quantity) AS total_out
  FROM public.withdrawal_items wi
  JOIN public.withdrawal_orders wo ON wo.id = wi.order_id
  WHERE wo.status IN ('approved', 'completed')
  GROUP BY wi.item_id
) out_sum ON out_sum.item_id = i.id;

ยอดคงเหลือสินค้าคำนวณจากผลรวมการรับเข้า (Stock In) ลบด้วยผลรวมการเบิกจ่ายที่อนุมัติแล้ว (Withdrawal Approved)
